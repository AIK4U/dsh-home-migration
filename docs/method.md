# 方法：闸门先行的搬迁

> 这份文档的目标是**照着做**。命令给的是形状，`<NEW_ROOT>` / `<OLD_ROOT>` 换成你自己的路径。
> 所有涉及「家」的命令都要求宿主**已停止**（尤其是要改登记表与会话头的那几步）。

---

## 1. 三条铁律

1. **闸门先行。** 判据不返回 0，就**不许重指、不许起 app**。判据的实现只能有一份
   （`tools\check-session-collisions.ps1`），控制器 / 切换器 / 验收三处都调它——**规则不会漂移**。
2. **失败不许硬撑。** 任一阶段失败就停在那里：**旧根在验收全绿之前，一个字节都不删。**
   重指阶段要自带自动回滚（把联接指回旧根）；回滚也失败就**什么都别删**，叫人手工跑回滚器。
3. **旧根还在的时候，它才是退路。** 「先把旧根删了再看」= 自断退路。

---

## 2. 前置：先搞清楚「谁在跑、谁的家在哪」

**这一步不能省，而且必须取当前进程的父链**——不能拿上一轮的 PID 或上一轮的结论推理。

实例（真实踩过）：一轮里判定「网页端执行者是桌面端的子进程，关桌面端会连带杀掉它」，
差点让用户关掉唯一还活着的执行者。**下一轮用父链一查就翻了**：
用户另开窗口起的进程，父链是 `explorer → cmd → powershell → node`，与桌面端**无关**。

```powershell
# 进程父链：逐级取 ParentProcessId
Get-CimInstance Win32_Process | Select-Object ProcessId, ParentProcessId, Name, CommandLine

# 端口归属：确认旧壳的端口真的空出来了、执行者的端口在
netstat -ano | findstr ":<旧壳端口> :<执行者端口>"
```

**判据**：

- 要搬走的壳，它的端口**必须没有** LISTENING；
- 执行者的壳**必须**在；
- 执行者必须是「家已经在新家」的那一个（否则你会在搬的过程中把自己的家抽走）。

> 注意：执行者壳的 `DSH_HOME` 可能来自它自己的启动脚本里的显式赋值，**不是**注册表/User 变量。
> 所以「User 变量已经是新值」**不能**用来推断执行者住在哪。

## 3. 十一步流程（实测退出码全 0）

以下每一步**先干跑，再落盘**；带 `-Apply` 的才写盘。所有动作**在同一个停机窗口里连续完成**。

| # | 动作 | 判据（必须看到） |
|---|---|---|
| ① | **身份核对**：进程父链 + `netstat` | 旧壳端口空出来；执行者壳在 |
| ② | **解桶碰撞（干跑）** | 列出待处理处数；**不建任何备份目录** |
| ③ | **会话碰撞闸门**（新家、旧家各一次） | 两次都 `duplicates: 0`；（诊断旧问题时旧家是 0 / 新家是 27 那种对照） |
| ④ | **单向同步器**（先干跑，再 `-Apply`） | 列出 / 落盘的文件清单；按名映射，**绝不造重复** |
| ⑤ | **`fix-paths.mjs apply <新家>` → `verify <新家>`** | **`verify: sessions=<实际会话总数> bad=0`**（数字偏小 ⇒ 工具盲区回来了） |
| ⑥ | **路径改写趟**（干跑 → `-Apply`） | 见第 5 节：**跑完同步必须补这一趟** |
| ⑦ | **逐字复核**关键配置里的根路径 | 见第 5 节的两处；必须**逐字**等于新家路径 |
| ⑧ | **再跑 `fix-paths verify` + 两道闸门** | `bad=0`；`duplicates: 0`；工作区路径复核「通过」 |
| ⑨ | **`adopt` 阶段**（只重指、不复制） | 内含闸门；失败自动回滚 |
| ⑩ | **带记录仪拉起 app** | stdout/stderr 落盘到 `<新家>\logs\app-*.log` |
| ⑪ | **验收** | 逐项清单全绿（第 6 节），最后一行 `VERIFY: PASS` |

命令形状（`$mh` = 搬迁工具目录，`$new` = 新家，`$old` = 旧家）：

```powershell
# ② 解碰撞（干跑）
node "$mh\resolve-bucket-collisions.mjs" $new "$new\档案\bucket-collision-backup-<时间戳>"

# ③ 闸门（两道，新旧各一次）
powershell -NoProfile -ExecutionPolicy Bypass -File "$mh\check-session-collisions.ps1" -DshHome $new
powershell -NoProfile -ExecutionPolicy Bypass -File "$mh\check-session-collisions.ps1" -DshHome $old

# ④ 单向同步器
powershell -NoProfile -ExecutionPolicy Bypass -File "$mh\sync-to-new-home.ps1"          # 干跑
powershell -NoProfile -ExecutionPolicy Bypass -File "$mh\sync-to-new-home.ps1" -Apply   # 落盘

# ⑤ 会话头改写
node "$mh\fix-paths.mjs" apply  $new
node "$mh\fix-paths.mjs" verify $new

# ⑥ 改写趟
powershell -NoProfile -ExecutionPolicy Bypass -File "$mh\move-home.ps1" -Phase rewrite
powershell -NoProfile -ExecutionPolicy Bypass -File "$mh\move-home.ps1" -Phase rewrite -Apply

# ⑨ 重指（只重指、不复制；内含闸门；失败自动回滚）
powershell -NoProfile -ExecutionPolicy Bypass -File "$mh\move-home.ps1" -Phase adopt -Apply

# ⑩ 带记录仪拉起
powershell -NoProfile -ExecutionPolicy Bypass -File "$mh\launch-with-log.ps1"

# ⑪ 验收
powershell -NoProfile -ExecutionPolicy Bypass -File "$mh\move-home.ps1" -Phase verify
```

**为什么必须一个窗口做完**：同步器的增量复制会读旧树，把新家**已修好的登记表与会话头覆盖回旧路径**。
窗口中间起一次 app，就会看到「登记表说一条路径、会话头说另一条」——正是「对话消失」的形状。

## 4. 重指阶段做什么（`adopt`）

四件事，缺一不可：

1. **闸门**（重复 ID 不为 0 就拒绝）；
2. 把 `%USERPROFILE%\.dsh` / `.mdcg` 两个联接重指到新家；
3. `Complete-Switch`：写 User `DSH_HOME` + **广播 `WM_SETTINGCHANGE`** + 换启动项 +
   交接看门狗 + 改 User `PATH` + 同步救生舱清单；
4. 任何一步失败 → **自动把联接回滚回旧家**。

两个容易漏的点：

- **不要闸执行者自己的端口**。闸门只针对要搬走的那个壳的端口——执行者就在另一个端口上，
  闸掉自己就没法搬了。
- **看门狗必须交接**。它用**全局单实例互斥体**：搬迁后若仍在跑的是旧根的看门狗，
  它在旧根被删后只会「找不到根 → 静默空转」，**却仍占着互斥体让新根的看门狗永远起不来**。
  所以重指要「按命令行匹配（排除自身）结束旧看门狗 → 启动新看门狗」，回滚方向对称。

---

## 5. 两个「跑完同步还会坏」的坑（必读）

### 5.1 单向覆盖：同步后**必须**补跑改写趟

同步器是**单向覆盖**：旧树里没改过的原文会盖掉新家已经改好的文件。
实测 **40 个文件被重写**（含两个壳的 `cordis.patch.yml` 与根启动脚本）。

后果不是报错，而是：网页端把**记忆根**指向一个**当时并不存在的目录**，并**安静地现建了一个空记忆库**。
⇒ **引擎照常启动、体检全绿、而记忆是空的。**

**所以第 ⑥ 步不能省，第 ⑦ 步必须逐字复核。** 复核两处（真实被覆盖坏过的）：

```powershell
Select-String -LiteralPath "$new\..\start-dsh.ps1" -Pattern 'memDir =|wsDir  ='
Select-String -LiteralPath "$new\profiles\desktop\cordis.patch.yml" -Pattern 'root:'
```

- 启动脚本里的记忆目录名 / 工作目录名必须是**新名**（中文名用字符码点拼装，见第 7 节）；
- 两个壳的补丁文件里的 `root:` 必须是**新记忆根**。

### 5.2 活库判据：`_keys.json` 在，才是活库

动任何「根」之前：**先看目标目录里有没有现成的 `_keys.json`。有 = 那才是活库。**
改完重启后第一件事是**问引擎自己**要 `root` 与节点总数，和历史量级对一遍。
**只看配置文件写对了没有，是把「配置对 ≠ 数据在那」这条坑再踩一遍。**

## 6. 验收清单（逐条，缺一不可）

1. 目标端口 LISTENING；目标壳的窗口出现；
2. 新家的 `logs\` 里**没有**新的 `startup-*.log`（有 ⇒ 宿主启动失败，读它前 40 行）；
3. **让人在 GUI 里点一次工作区**（能选 / 能新建）——**这是最终判据**，脚本全绿也不算数；
4. 问引擎自己：`root` == 新记忆根；节点数与历史量级对得上（不是 0、不是几十）；
5. 两个壳指向**同一个家、同一份记忆**（这正是搬迁的目的）——用两个壳各自的进程命令行核对 `profiles\<壳>` 路径；
6. 旧家的写入已完全停止（对比 `sessions\` 里最新文件时间）；
7. 记录仪的 `app-stderr-*.log` 为 0 字节或只有无害内容。

**成功后**：重启一次执行者壳，让它的内存态与盘上一致（重指之后它可能仍持有旧的登记表内存态，
盘上已经是新的——这种情况重启即可）。旧根**先别删**，观察一两天再走收尾。

---

## 7. 「删旧根」的收尾（最后一步，四道闸门）

顺序：**人工确认 → 验收 → 活树指向 → 进程占用**。

1. 确认词精确匹配（在 `.cmd` 里就拦掉）；
2. 验收清单必须全绿；
3. 两个联接与 `DSH_HOME` 必须已指新根；
4. **没有进程的命令行还含旧根路径**（旧看门狗就住在那里）。

然后：

- 删除用 `rd /s /q`——**它删联接本身、不会跟着联接走**。
- ⚠️ **绝不要**用 `Remove-Item -Recurse` 删旧根：旧树里有几百个联接，它会**走进包存储库把包删掉**。
- 建议先关掉两个壳与悬浮球再删：闸门 4 只看命令行，看不到「谁的工作目录还在旧根里」；
  真撞上会让 `rd` 只删一半，而脚本应**明确报错并停住**（fail-closed，不静默）。
- 删完复查新树的家 / 记忆目录 / 救生舱是否完好；**这一步之后回滚路径就断了**。

## 8. 搬迁时同时踩到的通用坑（与根因无关，但会让你以为根因没修好）

### 8.1 新目录「任何命令都跑不了」——所有者写入权限

现象：搬迁后在新工作目录里跑什么命令都失败，报

```
SetNamedSecurityInfoW failed (Win32 5)
```

即目录缺「所有者写入权限」，宿主无法给自己授权。

**修法（三步，缺一不可）**：补权限 → **回读验证** → **重跑原命令**。
（只补权不验证 = 下次仍然靠猜；不重跑 = 你不知道它修好了没有。）

### 8.2 路径要用**运行时推导**，不要「一次性替换」

实例：搬迁后 SSH 配置（用于发布身份的）里**仍写死旧根绝对路径**。
因为旧根还在，它**照常能用**；等旧根一删，它**无声断掉**。

**教训**：**替换过的字面量会烂掉，而烂掉时不报错。** 能推导的就推导（`$PSScriptRoot` 上溯、
批处理的 `%~dp0`、按形状扫盘），把「写死的绝对路径」当成技术债，而不是当成配置。

### 8.3 扫盘找根要在**嵌套根**下也成立

根从「平铺」变成「嵌套」之后，所有「按目录名扫盘找根」的兜底都会失效
（向上查找先命中新根，多半无害；但**真正的根定位**必须改成从脚本自身位置上溯）。
实测：两个维护脚本原先只靠「扫盘找名叫 `<旧目录名>` 的顶层目录」+ 一个未设置的环境变量 ⇒
在嵌套根下**永远找不到**；改成从 `$PSScriptRoot` 上溯三层后，干跑立刻报出正确的 `root:`。

## 9. 写这段工具链时踩的工程坑（照抄规矩，别重犯）

1. **空集合展开成 `$null`**：函数返回空集合 ⇒ 调用方拿到 `$null` ⇒ `Set-StrictMode` 下
   `$null.Count` 是终止错误。后果很阴：**「干净」那条路径崩了，「有重复」那条反而正常**。
   修法：调用处一律 `$dups = @(Get-... )`。**规矩：干净路径必须和故障路径一样被测到。**
2. **一次编辑把两行拼成一行**：`old_string` 吃掉行尾换行 ⇒ 文件被改坏。
   **规矩：每次改完立刻做语法解析检查，别攒到最后。**
3. **辅助函数的诊断输出一律 `Write-Host`**：`Write-Output` 会进入返回值，
   调用方拿到「消息 + 内容」的数组，拼进文件就把它写坏。
4. **只读自动变量**：`$home` / `$pid` / `$host` 等赋值抛的是**非终止错误**；
   而 `$ErrorActionPreference='Continue'` 会让脚本**带着错值继续跑完**，
   把文件写到错误的地方、还自信地打印「成功」。**这类赋值清单必须实测，不能靠印象**
   （实测为只读的包括 `home` / `pid` / `host` / `MyInvocation` / `ExecutionContext` / `PSVersionTable`
   / `true` / `false` / `null`）。
5. **脚本一律纯 ASCII**：无 BOM 的非 ASCII 脚本会被 PowerShell 5.1 按 ANSI 读成乱码；
   中文路径一律用 `[char]0xXXXX` 码点拼装。**代价是它同时也免疫了 grep 与批量替换**——
   实测扫出 25 处 / 16 个文件在用码点拼目录名，其中最致命的三处会让启动脚本把记忆根指向
   **不存在的目录**（= 静默空记忆）。所以**改名时必须在替换表里单独加一趟「字符码改名」**，
   并且用「抽真实码点 → 解码 → `Test-Path` 目标目录」来验证，不要验证自己写的字面量。
6. **JSON 里的路径是双反斜杠**：替换表只认单反斜杠 ⇒ `.json` 里的路径一处都没改到。
   改写流程要三趟：`raw` / 正斜杠 / **双反斜杠**。**这条对任何「磁盘路径进 JSON」的迁移都成立。**
7. **工具与记录不参与改写**：改写会改到搬迁工具**自己**（把它的旧根常量改掉 ⇒
   切换之后的验收与收尾全废），也会改到历史记录与 `.cmd` 里的码点名。
   维护一份**排除名单**（工具脚本、交接文档、历史档案）。
8. **复制工具会跟进联接**：`robocopy` 默认把目录联接**物化**成真实文件——
   实测 482 个联接被展开成 43,419 个文件塞进目标。修法：加 `/SJ /SL`。
   **且 `robocopy` 的退出码不等于复制完整**，必须逐目录数文件。
9. **环境变量到达不了已运行的 Explorer**：改完持久化 User 变量后从开始菜单启动，新进程仍可能继承旧值，
   应用会照旧从旧家启动。修法：**广播 `WM_SETTINGCHANGE`**，并且在启动器**自己进程里**先设
   `$env:DSH_HOME` 再 `Start-Process`。
10. **「按名字扫盘」的闸门必须报错而不是放行**：家不存在时要**硬报错**，不能静默返回「干净」。

## 10. 失败处置表（照着做，别即兴）

| 症状 | 处置 |
|---|---|
| 同步器拒绝（exit 1） | 读它打印的原因；**它什么都没写**，把原因发出来 |
| 改写后 `verify` 的会话数不对 | 工具盲区回来了，查 `fix-paths.mjs` 取最大代的那个函数 |
| 闸门不为 0 | **不要重指**。先解碰撞，再回到改写步 |
| 重指阶段报 FAILED | 它已自动回滚；叫人双击回滚器，把原文发出来 |
| app 起不来 | 把 `<新家>\logs\app-stderr-*.log` 与 `app-stdout-*.log` **全文**拿出来——**这次一定有证据** |
| app 起来了但工作区仍不可用 | 做日志取证：**别慌着回滚**，先把 stderr 拿到手 |
| 新工作目录里任何命令都跑不了 | 见 8.1：补权限 + 回读验证 + 重跑 |
| 一切看起来都好 | 见 5.2：问引擎自己，核对数据在不在 |

## 11. 这套方法里「可能没做到」的部分

- 本文的命令形状来自当时的工具链；`<你把工具重命名之后>` 参数名要对齐，**不要照抄不认识的名字**。
- 「等 15 秒再点工作区」这条**是未证的可疑点**，不是已验证的对策（见 `root-cause.md` §7）。
- 若你的宿主在启动失败时**会**写日志，那么第 3 节 ⑩ 的「记录仪」就没有那么关键；
  但**先确认它到底会不会写**，再决定要不要依赖它。
